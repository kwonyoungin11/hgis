# 문화재인트라넷

이 스킬은 ka-hgis 프로젝트 전용이다. 사용자 요청과 현재 코드가 우선이며, 과거 성공 기록을 새 오류의 원인으로 추정하지 않는다.

Browser cpp/h를 `build/recovery/before-heritage-long-wait-20260913-175939/`로 복원했다. 30초 대기·팝업 닫기 지연·전체 건수 표시 변경을 함께 되돌렸으며 PID35732 기준의 두 파일과 해시가 같다. 5초로 줄이는 제안은 구현하지 않았다. 실제 다운로드 완료·저장 파일 확인·기존 ZIP/SHP 검사·동기 적재 후 다음 자료로 진행하는 원래 계약을 유지한다. 새 실사용 성공을 확인한 것으로 기록하지 않는다.

- 성공 버전 확인이나 복원에는 [성공 기준과 장애 기록](references/success-state.md)을 읽는다. 단일 지정유산 성공과 여섯 종류 전체 성공을 구분한다.
- 사용자가 범례나 그룹 메뉴 하나만 요청하면 해당 표시 경로만 변경한다. 다운로드, 로그인, 타이머, HTTP 재시도, 번호 생성까지 묶어서 바꾸지 않는다.
- 사용자가 확인한 성공을 빌드 성공으로 대체하지 않는다. 소스 일치, 재컴파일, 실제 파일 수신, 지도 적재, 실사용 속도를 별도 사실로 보고한다.

## 유지할 실행 계약

1. 현재 조사구역의 시·군을 결정하고 사용자가 확인한다. 전국 다운로드 차단을 유지한다.
2. 앱 내 Qt WebEngine으로 공식 로그인·서약·자료 종류·시군 선택·검색을 진행한다. 화면이나 선택 결과를 확인한 뒤 다음 단계로 넘어간다.
3. 각 자료에서 공식 **전체다운로드 버튼을 한 번** 실행한다. 개별 행 반복 다운로드나 별도 수제 HTTP 요청으로 바꾸지 않는다.
4. 실제 `DownloadCompleted`를 받고 저장 파일 존재와 크기를 확인한다. 이어 ZIP/SHP 검사와 지도 적재가 성공한 뒤에만 다음 자료로 진행한다.
5. 지정유산, 현상변경허용기준, 매장유산유존지역, 문화유적분포지도, 지표조사구역, 발굴조사구역을 순차 처리한다. 명시적인 검색 0건은 기록하고 건너뛸 수 있지만 실패를 0건이나 성공으로 바꾸지 않는다.
6. 작은 진행 창으로 단계·수신 상태·실패를 표시한다. 사이트는 자세히에서 열고, 전체 완료 후 진행 창을 숨긴다. 유산 레이어는 위성/지적보다 위에 놓는다.

`KaHeritageBrowser.cpp/h`는 UI·다운로드 상태, `HeritageIntranetFlow.cpp`는 공식 화면 스크립트, `HeritageImport.cpp`는 검사·적재, `MainWindow::importHeritageDataset`은 동기 적재 성공 여부를 담당한다.

## 자료와 진단

- 계정은 저장된 설정을 사용한다. 계정 값·쿠키·CSRF를 소스, 스킬, 로그, 화면 캡처에 추가하지 않는다.
- 자료는 동국문화재연구원 소유다. 원본/가공 SHP를 포터블·제출 자료·저장소·스킬에 포함하지 않는다.
- 저장은 `%LOCALAPPDATA%/ka-hgis/ka-hgis/주변유적/` 아래 로컬 경로를 유지한다. 사용자 원본 조사를 진단 중 변경하지 않는다.
- 진단은 `<시도 시군>/receipts/진단.txt`, 해당 `requests-*.txt`, `D:/hgis/build/qa/heritage-debug.txt`를 필요한 시각만 읽는다. 오래된 요청 기록의 쿼리는 출력 전 가린다.
- 0바이트 완료 신호는 성공이 아니다. 파일 수신 전 지연, 실제 전송 시간, 압축 검사, 지도 적재 시간을 분리한다. 다른 도시의 시간 비교만으로 서버/코드 원인을 단정하지 않는다.

## 복원과 빌드

복원은 사용자 요청 범위의 변경만 대상으로 한다. 복원 전 현재 파일을 별도 백업하며 기존 미커밋 작업을 보존한다.

- PID 15408의 **실제 실행 파일·소스·빌드 설정·해시 명세**는 `D:/hgis/build/recovery/heritage-user-confirmed-pid15408-20260913/`에 보존되어 있다. 이 확정본은 덮어쓰지 않는다. 네 파일만 있는 과거 백업으로 대신하거나 새로 만든 빌드를 동일 실행 파일이라고 부르지 않는다.
- 사용자가 실사용 확인을 맡겠다고 지시했다. 새 지시가 없으면 에이전트가 자동 다운로드·실서버 비교·조사 조작을 하지 않는다. 코드 변경 시 필요한 빌드 후 앱을 열고 사용자 확인을 기다린다. 스킬·문서만 바꾸는 작업에는 앱 빌드·재시작이 필요 없다.

**Copy-Item은 과거 수정 시간을 유지한다.** 과거 `.cpp/.h`가 현재 `.obj`보다 오래되면 증분 빌드가 재컴파일을 생략할 수 있다. 특히 클래스 멤버가 달라진 헤더와 구현이 섞이면 힙 손상이 난다.

- 복원한 소스/헤더의 수정 시간을 현재로 갱신하거나, 해당 타깃을 명시적으로 재빌드한다.
- 로그에서 영향받은 구현, 호출자, Qt MOC의 재컴파일을 확인한다. 파일 SHA256 일치만으로 복원이 끝났다고 하지 않는다.
- 기존 환경을 사용한다: `. ./scripts/dev-env.ps1`, `cmake --build --preset release --target ka-hgis`.
- 앱은 `powershell -NoProfile -ExecutionPolicy Bypass -File D:/hgis/scripts/run-ka-hgis.ps1`로 연다. exe 직접 실행이나 dist 대체 실행은 하지 않는다.
- 빌드 후 사용자가 확인하도록 앱을 여는 현재 작업 방식을 따른다. 실행 중 앱을 강제 종료하거나 저장 대화상자를 자동 폐기하지 않는다. 자동 실서버 재실행/테스트 범위는 현재 사용자 지시를 따른다.
- 커밋·푸시·포터블·dist/L: 복사는 별도 요청이 있을 때만 한다.

## 범례를 이어서 수정할 때

`LayoutService::tuneSheetLegend`, `KaDrawingStudio`, `HeritageSiteLegend`의 현재 상태와 설치된 QGIS 헤더를 확인한다. 도면 범위 필터, 번호 생성, 자동 열 배치는 서로 다른 기능이다.

범례가 길다는 신고만으로 시군 전체가 표시된다고 판단하지 않는다. 현재 QGIS 필터의 확인 근거는 [도면 범례 상태](references/legend-state.md)를 읽는다.

범위 필터는 우선 QGIS의 연결 지도/범례 필터를 사용한다. 다운로드 중 도형 전체 조회·레이어 복제·반복 번호 계산을 새로 연결하지 않는다. 원본 렌더러·SHP를 바꾸지 않고 도면의 범례 모델에 적용한다. PID 15408 명세의 관련 소스 해시를 기준으로 변경 범위를 확인한다. 번호·자동 열·그룹 일괄 라벨은 현재 제거되어 있으므로 새 요청 없이 다시 넣지 않는다.
