# 주변유적 자동 받기 작업 계획 (국가유산청 GIS통합인트라넷)

작성 2026-09-10 밤. 작성 시점에 사용자는 맥북(집)이고 개발은 다음 날 사무실 메인 PC에서 시작한다.
이 문서만 읽고 바로 착수할 수 있게 쓴다. **확인된 사실**과 **사무실에서 확인해야 할 것**을 구분한다.

---

## 1. 목표 한 줄

조사자가 조사구역을 그리면, 그 **시/군의 국가유산 공간정보(5179 SHP)** 를 인트라넷에서 자동으로 받아
**유적명·정보를 붙인 참조 레이어**로 화면에 올린다.

## 2. 사용자 흐름 (승인된 것)

1. 조사자가 **조사구역을 그린다**
2. 앱이 그 도형에서 **시/군을 판정한다**
3. 인트라넷 로그인 → **서약서 동의 체크까지 자동** → 그 **시/군만** 검색 → 다운로드
4. `조사폴더/주변유적/`에 원본 보관 + 영수증 기록
5. **시/군 전체를 그대로** 참조 지도로 올린다 — 1km 로 자르지 않는다. 범위 판단은 사용자가 한다
6. 기존 「주변유적 500M·1000M 표시하기」 버튼은 그대로 둔다. 필요하면 사용자가 그때 쓴다

## 3. 확정된 제약 (사용자 지시, 임의로 바꾸지 말 것)

- **시/군까지만.** 읍/면/동·리 이하로 쪼개거나 전국을 훑는 경로를 만들지 않는다. 요청 단위는 시/군 하나.
- **서약서 동의 체크까지 자동으로 한다.** 단, **동의 시각과 서약서 원문을 영수증으로 남긴다**
  (`조사폴더/주변유적/receipts/`). 조용히 지나가지 않는다.
- **배포하지 않는다. 이 자료는 문화재연구원들의 재산이다.** 코드로 막을 것:
  - `조사폴더/주변유적/` 안에만 둔다
  - **포터블 패키지에 싣지 않는다** (`scripts/make-portable.ps1` 이 VWorld 키·NGII 계정을 싣는 것과 다르다)
  - **제출용 SHP 패키지에 섞지 않는다** — 제출물은 조사 성과물만
  - 참조 지도로만 올리고 조사 데이터와 분리한다 (`LayerOps::markReferenceLayer`,
    `LayerOps::placeInLegendGroup(project, layer, "참조 지도")`)
- **속성을 보존한다.** 수치지형도와 정반대다. 수치지형도는 밑그림이라 한 레이어로 합치고 속성을 버렸지만,
  주변유적은 **유적명과 정보가 붙어 있어야** 클릭해 읽고 보고서에 쓴다. 자료 종류별로 레이어를 나눈다.
- 계정은 소스·문서·로그에 남기지 않는다. 값을 화면에 찍지 않는다.
- 실패를 성공으로 처리하지 않는다. 사이트 구조가 바뀌면 그렇다고 말한다.

### 4.1 확인된 화면 흐름 (2026-09-11, 사용자가 직접 확인)

1. `https://intranet.gis-heritage.go.kr/` 접속
2. 로그인 — 아이디/비밀번호 입력 후 「로그인」
3. **튜토리얼 안내가 매번 뜬다.** 「튜토리얼 나가기」를 눌러 닫아야 화면이 잡힌다
   (하단에 「다시 보지 않기」 체크가 있으나 매번 다시 뜨는 것으로 보인다 — 자동화는 매번 닫는다고 가정한다)
4. 우측 위 **마이페이지** 또는 상단 **데이터 개방 › 국가유산자료 다운로드**
5. **국가유산 공간정보 원본자료 사용 서약서** 팝업 — 「위 서약서에 동의합니다」 체크 후 「확인」
6. 탭 6개(지정유산·현상변경허용기준·매장유산유존지역·문화유적분포지도·지표조사구역·발굴조사구역)
7. **시/도 선택 → 시/군/구 선택까지만** 하고 검색. 그 아래(읍면동·리)는 건드리지 않는다
8. 결과를 받아 hgis 로 올린다. **결과가 여러 페이지일 수 있다** — 페이지를 넘기며 모아야 한다
   (하단 「선택다운로드」/「전체다운로드」, 우측 「10개씩 보기」 선택)

서약서 원문(2026-09-11 화면) 요지 — 영수증에 그대로 남긴다:
「국가공간정보 기본법」 제37조·제40조 등 준수 / 성과물은 제공조건에 따라 공유 / **제3자 양도·대여 금지** /
제공조건 외 사용으로 생긴 법적 분쟁의 책임은 제공받은 자에게 있음.

### 4.2 로그인 구조 — 확인함 (2026-09-11, 실제 DOM)

**루트는 frameset 이다.** `https://intranet.gis-heritage.go.kr/` 는 프레임 두 개로 되어 있다:

| 프레임 | 주소 |
|---|---|
| `top` | `about:blank` |
| `main` | `/user/checkNet.do` ← 로그인 폼이 여기 있다 |

`QWebEnginePage::runJavaScript()` 는 기본으로 최상위 프레임에서 돈다. 그래서 루트로 들어가면
로그인 폼이 안 보인다. **`/user/checkNet.do` 로 바로 들어가면 프레임 없이 같은 폼을 만난다** —
자동화는 이쪽을 쓴다 (`HeritageIntranetFlow::loginUrl()`).

폼 구조:

| 요소 | 값 |
|---|---|
| form | `name="loginForm"` · `action="/j_spring_security_check"` · POST (Spring Security) |
| 아이디 칸 | `input#userId` (type=text, name=userId) |
| 비밀번호 칸 | `input#pwd` (type=password, name=pwd) |
| 로그인 버튼 | `button` · `onclick="goLogin();"` |
| 숨은 칸 | `#RSAModulus`, `#RSAExponent`, `#USER_ID`, `#USER_PW` |
| 기타 링크 | `javascript:goRegiUsr();` (회원등록) · `javascript:idpwFind();` (아이디/비밀번호 찾기) |

**중요 — 브라우저에서 RSA 로 암호화한다.**
보이는 칸(`userId`/`pwd`)의 값은 그대로 전송되지 않는다. 페이지의 `goLogin()` 이
`RSAModulus`/`RSAExponent` 로 암호화해 숨은 칸 `USER_ID`/`USER_PW` 에 넣고 폼을 보낸다.
따라서 **평문을 `/j_spring_security_check` 로 직접 POST 하면 로그인되지 않는다.**
우리가 암호화를 흉내내지 말고 **칸을 채운 뒤 `goLogin()` 을 부른다.**
`tests/test_heritage_flow.cpp` 가 이 규칙을 붙잡는다(직접 POST 하는 코드가 들어오면 실패한다).

## 5. 사무실에서 먼저 확인할 것 (미확인)

착수 전에 이것부터 실제 응답으로 확인한다. 추측으로 구현하지 않는다.

1. **다운로드 요청의 실제 형태.** 행 아이콘 / 선택다운로드 / 전체다운로드가 각각 어떤 요청을 보내는지
   (DevTools Network). 폼 POST 인지, 파일 ID 배열을 넘기는지, 응답이 ZIP 직접인지 별도 전송 페이지인지.
   수치지형도는 INNORIX 전송 페이지로 넘어갔다. 여기도 그런지 확인.
2. **시/군 단위 「전체다운로드」가 되는지.** 시/군으로 검색한 결과 전체를 한 번에 받을 수 있으면 그 경로를 쓴다.
   안 되면 페이지를 돌며 선택다운로드를 반복해야 한다 — 이 경우 요청 간격과 총 건수 상한을 정한다.
3. **받은 파일의 실제 구조.** SHP 세트인지 ZIP 중첩인지, 좌표계가 정말 5179 인지 (`.prj` 확인),
   속성 컬럼 이름(유적명·소재지·지정번호 등)과 인코딩(CP949 여부).
4. **서약서 팝업이 뜨는 조건과 지속 시간.** 세션당 한 번인지 매 진입인지. 동의 상태가 서버에 남는지 쿠키인지.
5. **시/군 드롭다운의 값 목록.** 시도 선택 → 시군구 옵션이 어떻게 채워지는지(Ajax 인지 정적인지),
   그리고 그 표기가 `KoreaRegionCatalog` 의 표기와 일치하는지 (예: "안동시" vs "경상북도 안동시").

## 6. 재사용할 기존 부품 (이 리포에 이미 있음, 확인함)

수치지형도가 같은 모양을 이미 뚫어 놓았다. **새로 만들지 말고 같은 틀을 쓴다.**

| 부품 | 파일 | 하는 일 |

| 계정 | `src/core/TopographicSettings.{h,cpp}` | `<userConfigDir>/ngii-account.ini` 의 `ngii/username`,`ngii/password`. 포터블은 `config/ngii-local.ini` 를 대체 파일로 읽는다 |
| 보관함 | `src/core/TopographicArchive.{h,cpp}` | 원자적 압축 해제, 해시, 원본 보존 |

| 범위 패널 | `src/app/KaTopographicScopePanel.{h,cpp}` | 작업 세대 관리, 취소, 늦은 결과 폐기, 진행 표시 |

같은 함수를 그대로 쓰지 말고, 자료 종류별 레이어를 유지하는 경로를 따로 두거나 옵션으로 가른다.

## 7. 새로 만들 것

### 7.1 시/군 판정 — `HeritageRegionResolver` (신규)

**확인함: 기존에 「좌표 → 시/군」 을 해 주는 것이 없다.**
- `AdminBoundaryService` 는 **이름 → 경계 도형**(VWorld `LT_C_ADEMD_INFO`)이다. 방향이 반대다.
- `KoreaRegionCatalog` 는 정적 목록(`allSido/citiesOf/dongsOf`)이다.

선택지 (사무실에서 하나 고를 것):
1. **VWorld 좌표→행정구역 API** (reverse geocode). 앱에 이미 VWorld 키가 있어 제일 간단하다.
2. 프로젝트에 이미 올라와 있는 **`LSMD_ADM_SECT_UMD_*` 행정경계 SHP** 로 점-in-폴리곤. 인터넷 없이 되지만
   그 레이어가 항상 있지는 않다.
3. 1을 기본, 실패 시 2로 폴백.

입력은 **조사구역 도형의 중심점**(5186/5187 → 5179 또는 4326 변환). 출력은 `{시도, 시군구}` 와 신뢰도.
**사용자에게 판정 결과를 보여 주고 바꿀 수 있게 한다** — 시/군 경계에 걸친 조사는 흔하다.

### 7.2 사이트 자동화 — `HeritageIntranetBrowser` (신규, `KaTopographicBrowser` 복제 아닌 공통화 검토)

단계: 로그인 → 서약서 동의(체크+확인, **영수증 기록**) → 탭 선택 → 시도·시군구 선택 → 검색 →
결과 수집 → 다운로드 → 완료 대기.

- 공식 화면은 숨기고 **단계·실제 전송량·완료 개수·실패 사유**만 보여 준다 (수치지형도와 같은 원칙)
- 사이트 화면이 바뀌어 요소를 못 찾으면 **그렇다고 말하고 멈춘다.** 성공으로 처리하지 않는다

### 7.3 보관·적재 — `HeritageArchive` / 적재 경로

- `조사폴더/주변유적/{원본,SHP,index,receipts}` — 수치지형도의 `지형도/` 와 같은 모양
- 자료 종류별 레이어: `매장유산유존지역`, `문화유적분포지도`, `지표조사구역`, `발굴조사구역`,
  `지정유산`, `현상변경허용기준`
- **속성 보존**, 유적명 라벨은 기본 꺼짐(레이어가 많으므로) — 사용자가 켠다.
  지도 위 글자 대신 **범례에서 유적명을 읽는다** (7.5)
- 인코딩은 `LayerOps::prepareShapefileEncoding` / `setShapefileEncoding` 재사용 (CP949 대비)

### 7.4 화면 — 버튼 하나, 종류별 고정 색

**버튼 하나로 끝나야 한다.** 조사자가 조사구역을 그린 뒤 버튼 한 번 누르면
시/군 판정 → 로그인 → 동의 → 검색 → 다운로드 → 적재까지 앱이 알아서 한다.
중간에 물어보는 것은 **시/군 판정 결과 확인** 하나뿐이다(경계에 걸친 조사가 흔하므로).

- 자리: 리본 **「좌표 정합」** 그룹의 기존 `주변유적 500M·1000M 표시하기` 옆.
  기존 버튼은 그대로 둔다 — 그건 이미 올라온 레이어에 버퍼를 그리는 것이고, 새 버튼은 자료를 받아 온다.
- 이름 후보: **「주변유적 받기」** (기존 버튼과 헷갈리지 않게 「표시」와 「받기」로 가른다)
- 진행 표시는 수치지형도와 같은 원칙: 공식 화면은 숨기고 **단계·전송량·완료 개수·실패 사유**만 보여 준다
- 이미 그 시/군을 받아 두었으면 다시 받지 않고 보관본을 올린다 (수치지형도의 「보관 도엽 N장 사용」과 같은 문구)

### 종류별 고정 색 (범례 통일)

**한 종류는 언제나 한 색이다.** 조사·보고서·인쇄에서 같은 색이 같은 뜻이어야 한다.
아래는 제안값이며 사용자가 바꾸면 그 값을 SSOT 로 삼는다. 코드에 표를 한 곳에만 두고 거기서만 읽는다.

| 자료 | 색 | 비고 |
|---|---|---|
| 지정유산 | `#8E44AD` 자주 | 법정 지정. 가장 강한 규제 |
| 현상변경허용기준 | `#E67E22` 주황 | 규제 기준 |
| 매장유산유존지역 | `#2E86C1` 파랑 | 매장유산 |
| 문화유적분포지도 | `#27AE60` 초록 | 분포 정보 |
| 지표조사구역 | `#16A085` 청록 | 조사 이력 |
| 발굴조사구역 | `#A0522D` 갈색 | 조사 이력 |

**색 사용 규칙**

- **빨강은 쓰지 않는다.** 조사구역·유존지역평가지역이 빨강이다. 조사 성과물과 참조 자료가 섞이면 안 된다
- **회색도 쓰지 않는다.** 수치지형도 밑그림이 `#808080` 이다
- 면은 **테두리만** 그린다(속 빈 면). 채우면 위성·지적·수치지형도를 가린다.
  채움이 필요하면 알파 0 또는 아주 옅게 — 이 앱의 「라벨 위 덧그림」 2차 패스가 **완전 투명이거나
  완전 불투명한 것만** 대상으로 삼으므로 어중간한 반투명은 피한다 (`LayerOps::paintsFullyOpaque` 참고)
- 선폭은 조사 도형보다 얇게. 밑그림(0.2mm)보다는 굵게 — 0.3~0.4mm 권장
- 유적명 라벨은 **기본 꺼짐**. 종류가 여섯이라 다 켜면 글자가 화면을 덮는다. 사용자가 켠다.
  **유적명은 라벨이 아니라 범례로 전달한다** — 7.5 참고

### 7.5 범례 — 종류별 색 한 개, 유적명 한 줄씩

**범례에 유적명이 하나씩 들어가야 한다.** 색은 자료 종류마다 하나(7.4 표), 줄은 유적마다 하나다.
보고서 도면에서 독자가 어느 도형이 어느 유적인지 범례로 읽는다.

범례 모양:

```
참조 지도
  매장유산유존지역        ← 레이어 이름 (색은 이 종류의 고정색 하나)
    ■ 안동 ○○유적
    ■ 안동 △△유적
    ■ 안동 □□리 유적
  지표조사구역
    ■ ○○ 공동주택 부지
```

- **구현**: 자료 종류별 레이어에 `QgsCategorizedSymbolRenderer(유적명필드, cats)` 를 건다.
  카테고리마다 심볼을 만들되 **색은 전부 7.4 표의 같은 값**을 준다.
  `QgsRendererCategory(값, 심볼, 유적명)` 의 **세 번째 인자가 범례 글자**다.
- **`applySoilCategoryStyle`(`src/core/LayerOps.cpp`)과 같은 틀이되 다른 점이 둘 있다.** 그 함수를 그대로 쓰지 말 것:
  1. 그건 값마다 색을 바꾼다(황금각 색상환). 주변유적은 **한 종류 한 색**이다
  2. 그건 200개를 넘으면 단색으로 떨어진다. 주변유적은 그러면 유적명이 범례에서 사라진다 —
     문화유적분포지도는 시/군 하나에 수백 건이 나온다. 상한을 따로 두고(권장 2000),
     넘으면 **조용히 단색으로 떨어뜨리지 말고 사용자에게 말한다**
- **빈 값 처리**: 유적명이 빈 레코드는 `기타`/`무명` 카테고리로 반드시 받아 준다.
  카테고리가 없으면 **그 폴리곤이 아예 안 그려진다** (같은 함정이 `applySoilCategoryStyle` 에 주석으로 남아 있다)
- **유적명 필드 이름은 5장 3번에서 실제로 확인한 컬럼을 쓴다.** 추측으로 `name`·`유적명` 을 박지 않는다.
  자료 종류마다 컬럼 이름이 다를 수 있다(지표조사구역은 **사업명**으로 검색한다 — 유적명이 아닐 수 있다)

**도면 범례는 인쇄 범위 것만 나온다 (이미 되어 있음)**

- `LayoutService::tuneSheetLegend()` 가 `setLegendFilterByMapEnabled(true)` 를 건다.
  화면에는 시/군 전체를 올려도 **도면에는 인쇄 범위에 든 유적만** 범례에 나온다.
  사용자 요구("화면엔 시/군 전체, 범위 판단은 사용자")와 그대로 맞물린다
- 다만 `tuneSheetLegend()` 는 세 조건을 통과한 레이어만 남긴다. 주변유적 레이어는 셋 다 통과해야 한다:
  1. `omitSheetLegendLayer()` 에 걸리지 않을 것 → `ka_hgis/omit_sheet_legend` 를 **켜지 말 것**,
     이름이 `지적`·`위성` 으로 시작하지 않을 것
  2. 레이어 체크가 켜져 있을 것 (`projectLayerChecked`)
  3. 연결된 `QgsLayoutItemMap` 의 레이어 목록에 있을 것 (`onLinkedMap`)
- 참고: `sheetLegendOmitsLayerName()` 목록에 **수치지형도가 없다.** 밑그림인데 도면 범례에 한 줄 나올 수 있다.
  4단계에서 같이 확인한다

**레이어창엔 종류만, 유적명은 도면 범례에만** (사용자 지시)

레이어창에는 `지정유산`, `발굴조사구역` 처럼 **종류 이름 한 줄씩만** 올라간다.
유적명 수백 줄은 **도면 범례에만** 나온다.

**가능하다.** 다만 QGIS는 **레이어 하나에 범례 구현이 하나**다 — 레이어창과 도면 범례가 같은
`QgsMapLayerLegend` 를 쓴다 (`src/core/DemColorRampLegend.h` 주석에 그대로 적혀 있다:
"One legend implementation is shared by the layer tree and layout legends").
그래서 **범례 구현 안에서 둘을 갈라야** 한다. 가를 근거는 이미 코드에 있다:

- `LayoutService::tuneSheetLegend()` 가 `setSyncMode(Manual)` + `resetManualLayers()` 를 부른다
  → **도면 범례는 프로젝트 트리가 아니라 자기 복제 트리**를 쓴다
  (`tests/test_workflow.cpp:4715` 주석: "tuneSheetLegend는 Manual 전용 트리를 쓴다")
- 이 앱의 도면 범례 경로는 **예외 없이 전부** `tuneSheetLegend()` 를 지난다
  (`KaDrawingStudio.cpp:2575·2587·2799·2814`, `LayoutService.cpp:586`)

구현은 `DemColorRampLegend` 와 같은 틀이다:

```cpp
class HeritageSiteLegend final : public QgsMapLayerLegend {
  QList<QgsLayerTreeModelLegendNode*> createLayerTreeModelLegendNodes(QgsLayerTreeLayer* node) override {
    QgsLayerTreeNode* root = node;
    while (root->parent()) root = root->parent();
    // 최상위가 프로젝트 트리면 = 레이어창. 아니면 = 도면 범례의 Manual 복제 트리
    const bool inPanel = m_layer->project() && root == m_layer->project()->layerTreeRoot();

    if (inPanel)
      return { 종류 색 견본 한 개 };   // 유적명 없음
    std::unique_ptr<QgsMapLayerLegend> def(QgsMapLayerLegend::defaultVectorLegend(m_layer));
    return def->createLayerTreeModelLegendNodes(node);   // 유적명 전부
  }
};
```

지켜야 할 것:

- 도면 쪽은 **기본 구현에 그대로 넘긴다. 손으로 노드를 만들지 않는다.**
  기본 노드에는 렌더러 rule key 가 붙어 있고, 그 키가 있어야
  `setLegendFilterByMapEnabled(true)` 의 **인쇄범위 걸러내기가 동작한다.**
  직접 만든 노드는 키가 없어 걸러지지 않고 **시/군 전체가 범례에 쏟아진다**
- 따라서 **렌더러는 유적명 카테고리 그대로** 두어야 한다. 패널을 비우겠다고 단색 렌더러로 바꾸면
  인쇄범위 걸러내기가 같이 죽는다
- 패널 노드를 0개로 돌려도 되지만 **색 견본 하나는 남기는 편이 낫다** — 레이어창에서 그 종류 색을 본다
- 비교는 `m_layer->project()->layerTreeRoot()` 로 한다. `QgsProject::instance()` 로 박으면
  자기 프로젝트를 쓰는 테스트에서 어긋난다
- `DemColorRampLegend::install()` 처럼 **이미 설치돼 있으면 다시 설치하지 않는** 가드를 둔다

**더 간단한 대안** (먼저 이걸로 눈으로 확인해도 된다): 패널 노드를 **접은 채로** 올린다
(`QgsLayerTreeLayer::setExpanded(false)`). 한 줄이고 위험이 없다.
다만 사용자가 펼치면 유적명이 나온다 — "레이어창엔 종류만" 을 글자 그대로 지키려면 위의 범례 구현으로 간다.

**부작용 관리**

- 성능: `setLegendFilterByMapEnabled` 는 지도 히트테스트를 돈다. 카테고리가 많으면 조판이 느려질 수 있다.
  4단계 실제 안동시 자료에서 **조판 미리보기 시간을 재고**, 느릴 때 대책을 정한다. 미리 추측으로 최적화하지 않는다

**검증 훅이 이미 있다**

`LayoutService::sheetLegendLabelDump(legend)` 가 범례의 모든 줄 글자를 개행으로 이어 돌려준다.
테스트에서 **유적명이 한 줄씩 들어갔는지**를 이걸로 확인한다 (설정값 확인이 아니라 실제 범례 내용 확인).

**선택 — 사용자 확인 필요**: 범례 줄에 번호를 붙이고 도면에도 같은 번호를 찍는 방식(`① 안동 ○○유적`).
고고학 보고서 도판에서 흔하다. 지금 계획에는 넣지 않았다. 원하면 그때 넣는다.

## 8. 작업 순서 (한 번에 하나씩, 각 단계 끝에 실제 확인)

착수 순서를 지킨다. 여섯 종을 한꺼번에 붙이면 사이트 화면 하나 바뀔 때 전부 멈춘다.

1. **5장의 미확인 항목을 DevTools 로 실제 확인**하고 이 문서에 적는다
2. **시/군 판정** 만 먼저 만든다. 조사구역 → 시/군 이름이 화면에 뜨고, 사용자가 고칠 수 있으면 끝
3. **매장유산유존지역 한 종**으로 로그인 → 동의 → 검색 → 다운로드 → 보관 → 적재를 **끝까지** 뚫는다
4. 실제 안동시 자료로 확인: 레이어에 뜨는가, **유적명·정보가 붙어 있는가**, 5179 인가, 원본이 보관되는가
5. 나머지 다섯 종을 같은 틀에 얹는다
6. 배포 금지 제약을 코드로 막고 **회귀 테스트로 고정**한다
7. 종류별 고정 색표를 한 곳에 두고 여섯 종에 적용한다. 색이 코드 여기저기 흩어지지 않게 한다
8. **범례를 붙인다.** 유적명 카테고리 렌더러 → `HeritageSiteLegend` 로 레이어창/도면 범례 가르기 →
   도면 범례에 유적명이 한 줄씩 나오는지 `sheetLegendLabelDump` 로 확인.
   3단계(한 종)에서 한 번 뚫고 5단계에서 나머지에 얹는다

## 9. 검증 방법

- **설정값이 저장됐는지가 아니라 실제 결과로 확인한다.** 화면 적재는 렌더 화소, 자료는 실제 속성값으로 본다
  (`docs` 의 기존 원칙, 그리고 이번 세션에서 값비싸게 배운 것)
- 실제 자료 재현 검사: 안동시로 한 번 전 과정을 돌리고 결과를 `build/qa/` 에 남긴다
- 회귀 테스트에 넣을 것:
  - 주변유적 레이어가 **포터블 패키지에 포함되지 않는다**
  - 주변유적 레이어가 **제출 SHP 패키지에 포함되지 않는다**
  - 시/군보다 좁은 단위 요청 경로가 없다
  - 서약서 동의 시 영수증이 남는다
  - 적재된 레이어에 유적명 속성이 살아 있다
  - 자료 종류별 색이 표의 값과 같다(빨강·회색을 쓰지 않는다)
  - 버튼 한 번으로 시/군 판정 확인 외에 추가 조작 없이 적재까지 끝난다
  - **도면 범례에 유적명이 한 줄씩 들어간다** — `LayoutService::sheetLegendLabelDump()` 결과에
    실제 유적명 문자열이 있는지로 확인한다
  - 한 종류의 범례 색이 여러 줄에 걸쳐 **모두 같은 값**이다 (유적마다 색이 갈리지 않는다)
  - **레이어창에는 종류 이름만 나온다** — 프로젝트 트리로 `QgsLayerTreeModel` 을 만들어
    `layerLegendNodes(node)` 가 1개(색 견본)인지로 확인한다. 같은 레이어를 도면 범례에서 보면 유적명이 다 나온다
  - 인쇄 범위 밖 유적은 도면 범례에 나오지 않는다 (지도 범위를 좁혀 `sheetLegendLabelDump` 가 줄어드는지)
  - 유적명이 빈 레코드도 그려진다 (카테고리 누락으로 사라지지 않는다)
  - 유적 수가 상한을 넘으면 조용히 단색으로 떨어지지 않고 사용자에게 알린다
- 마지막에 Release 전체 빌드 · CTest · smoke · (요청 시) 포터블

| `MainWindow::fetchNearbyHeritage` | 리본 「좌표 정합」의 **「주변유적 받기」 버튼** |

확인된 것:

- 레이어창 노드가 **1개**이고 `isEmbeddedInParent()` 다 — 종류 이름 줄에 색 견본만 붙는다
- 같은 레이어를 도면 범례 쪽 트리로 물으면 **유적명이 전부** 나온다
- 한 종류의 모든 카테고리 색이 같다
- 유적명이 빈 도형도 그려진다(받아 주는 카테고리가 있다)
- 유적명 필드가 없으면 **단색으로 걸되 그렇다고 말한다**
- 오목한(ㄷ 자) 조사구역에서도 대표점이 도형 안에 있다
- 「수원시 장안구」 → 「수원시」로 접힌다. 「강원도」 → 「강원특별자치도」
- 경계 밖 좌표에 **아무 시/군이나 돌려주지 않는다**

**버튼 한 번으로 끝까지 간다.**

조사구역 → 시/군 판정 → **확인 한 번** → 로그인 → 튜토리얼 닫기 → 다운로드 화면 → 서약서 동의
→ (종류마다) 탭 선택 → 시·군 선택 → 검색 → **전체다운로드**(없으면 전 행 체크 후 선택다운로드)
→ 여러 쪽이면 쪽을 넘기며 계속 → 받은 ZIP/SHP 를 조사폴더에 풀고 → **지도에 올린다**.
한 종류를 받을 때마다 바로 올리므로 여섯 종을 다 기다리지 않는다.

- 받은 자료: `조사폴더/주변유적/{원본,SHP,receipts}`
- 지도 배치: 「참조 지도」 그룹, 읽기 전용, 조사 데이터와 분리
- 색: 종류마다 하나(7.4). 범례: 유적명 한 줄씩(7.5). 레이어창: 종류 이름만
- 유적명 컬럼은 **실제 필드에서 고른다**(`HeritageImport::chooseNameField`). 추측으로 박지 않고,
  못 찾으면 그렇다고 말한다
- 서약서 동의 시각과 원문은 `receipts/서약서-<시각>.txt` 로 남는다

로그인 외 단계의 선택자는 실제 화면으로 아직 확인하지 못했다(`isVerified()==false`).
화면이 예상과 다르면 **그 자리에서 멈추고** 그때 화면에 무엇이 있었는지 창 아래에 보여 준다.
그 내용을 보고 선택자를 고친다 — 추측으로 덮지 않는다.

**작업 중 나온 사실 둘**

1. **조사구역 팔레트와 색 계열이 겹친다.** `KaSurveyAreaDialog` 의 조사구역 색 8종은
   빨강 `#DC2626` · 주황 `#EA580C` · 노랑 · 초록 `#16A34A` · 파랑 `#2563EB` · 남색 · 보라 `#7C3AED` · 갈색 `#92400E` 다.
   색만으로는 조사 성과물과 참조 자료를 가를 수 없다.
   **가르는 것은 「테두리만 vs 반투명 채움」이다** — 주변유적은 속을 비우고 조사구역은 채운다.
   빨강만 코드로 막았다(`HeritageStyle::isReservedColor`).
2. **QTest 출력은 `-o <파일>,txt` 로 파일에 남는다.** stdout 리다이렉트(`cmd /c exe > file`)로는
   PASS/FAIL 줄이 나오지 않는다. 10장에 적어 둔 것과 반대다 — 앞으로는 `-o` 를 쓴다.
