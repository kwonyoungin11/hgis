# 수치지형도 자동 받기 작업 계획

## 2026-09-09 최신 후속 범위

- 사용자 최신 요구: 반경 10km의 미보관 도엽을 모두 체크하고 신청서는 한 번 제출한다. 도엽별 반복 신청을 제거한다.
- 공식 `downloadMapData('1','online',items,null)`와 단일 `shbtInsertNRM.do`가 다중 항목을 지원한다. 최종 응답은 `nlippd.ngii.go.kr`의 INNORIX 전송 페이지로 이동한다.
- 설치 프로그램 없이 공식 SDK의 HTML5 모드를 사용한다. 같은 페이지에서 여러 파일을 200ms 간격으로 열면 큰 DXF 요청이 XML 탐색에 취소되는 현상을 실제 수신 검사에서 확인했다. 현재 목록에서 검증한 파일 ID 하나를 전송하고 Qt의 완료 후 다음 파일을 받는다. 이 순서는 앱 내부 처리이며 사용자는 추가 신청·클릭을 하지 않는다.
- DXF/XML 동반 파일 완료 후 해당 도엽의 메타데이터와 함께 SHP 준비로 넘긴다. 도엽별 원본 폴더를 유지하고, 좌표 검토 대상은 성공으로 표시하지 않으며 정상 도엽 처리를 계속한다.
- 계정은 더보기 설정, 공식 화면은 숨김, 실제 단계·파일 수신량·실패 사유는 표시한다. 바탕 화면의 현재 Release 연결로 검증한다. 포터블·커밋은 하지 않는다.
- 완료 조건: 실제 공식 다중 도엽 수신, 양성 실제 자료 SHP 변환·회색 0.2mm 참조 레이어 화소, 회귀 테스트·Release 전체 CTest·시작 검사 통과.

아래는 최초 계획의 이력이며 위 최신 요구가 우선한다.

사용자가 승인한 흐름은 HGIS 안의 현재 조사구역/화면 중심, 반경 지정 → 공식 1:25,000 DXF 도엽 선별 → 신청/전송 → 원본을 보존한 압축 해제 → 검증한 좌표계로 참조 지도 적재이다. 최신 지시로 로그인·신청·동의·최종 다운로드도 자동화 범위에 포함한다. 알 수 없는 개인정보는 만들지 않고 계정 정보는 코드·설정·로그에 저장하지 않는다. 로그인·인증 실패나 사이트 구조 변경을 성공으로 처리하지 않는다.

1. 기존 Browser/Catalog/ImportDialog를 이어 쓴다. MainWindow는 브라우저를 앱 탭에 넣는다. 별도 창이 발생하는 회귀를 먼저 재현한다.
2. 공식 격자와 실제 공개 검색 응답을 검증한다. `TopographicSheets`가 반경 후보와 경계를 계산한다. 다운로드 재고는 공식 포털 응답과 구분한다.
3. `TopographicArchive`가 중첩 ZIP을 별도 보관 폴더에 원자적으로 해제한다. 원본/완료 캐시는 보존하며 취소·불완전 파일은 적재하지 않는다.
4. `TopographicCatalog`가 DXF Layer 코드/도형 종류를 나누고 외부 JSON 코드표를 사용한다. `TopographicSourceCrs`가 공식 GRS80 메타데이터, 도엽과 실제 좌표 범위를 대조해 유일한 좌표계만 허용한다. 이 검사를 위성 영상 정합 검사라고 부르지 않는다.
5. `KaTopographicScopePanel`이 반경·경계·보관함·작업 세대를 관리한다. 받은 파일은 작업 스레드에서 준비하고 GUI 스레드에서 기존 ImportDialog의 검증 자료 적재 경로를 쓴다. 조사 변경 시 늦은 결과를 취소한다.
6. Browser의 공식 사이트 어댑터는 실제 확인한 선택기/함수만 사용한다. 진행 중 중복 신청 방지, 단일 도엽 순차 처리, 다운로드 완료 이벤트와 자료 메타데이터 연결을 검증한다. 알 수 없는 인증/전송 프로그램은 구체적인 대기 원인을 보여준다.
7. 범위·압축·DXF·CRS·임베딩의 집중 검사 후 Release 전체 빌드/CTest/시작 검사를 실행한다. 실제 HGIS 화면과 다운로드 전 과정을 확인해 완료/미검증을 구분한다. 사용자 원본 조사는 수정하지 않고 커밋하지 않는다.

분담: 격자, 압축/CRS, DXF 카탈로그/적재, 포털 어댑터는 서로 다른 파일에서 수행한다. 주 에이전트는 앱 연결·범위 패널·보관함과 통합 검증을 맡는다. 변경 후 독립 검토에서 비동기 수명과 실패 시 상태를 확인한다.
