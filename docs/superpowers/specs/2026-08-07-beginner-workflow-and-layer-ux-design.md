# 초보 발굴조사자 작업 흐름과 레이어 UX 설계

## 배경과 목적

이 프로그램의 프로젝트는 단순 지도 파일이 아니다. 현장 발굴조사자가 조사구역, 유구, GPS 기준점과 도면을 정해진 구조로 기록하고, 제출 가능한 PDF와 EPSG:5179 SHP 패키지까지 완성하는 작업 단위다.

따라서 기본 화면은 GIS 기능을 나열하는 대신, GIS 경험이 거의 없는 발굴조사 실무자가 다음 작업과 완료 조건을 즉시 알 수 있게 해야 한다. 전문 작업자는 기존 메뉴와 레이어 조작을 그대로 사용할 수 있어야 한다.

## 범위

이번 변경은 다음을 포함한다.

1. 조사 생성부터 제출까지의 7단계 안내와 완료 상태를 복원하고, 실제 프로젝트 상태에 연결한다.
2. VWorld 배경, 위성, 지적도, 하이브리드, 등고선을 용도별 아이콘과 한국어 설명으로 제공한다.
3. 레이어 목록의 드래그 재정렬, 삭제 버튼, Delete 키, 우클릭 삭제를 안전하게 제공한다.
4. 지적도와 위성 사진을 동시에 사용하거나 투명도를 조절하는 명확한 화면을 제공한다.
5. VWorld 키를 소스 코드에서 제거하고 사용자 설정에 저장한다.
6. 위 동작을 GUI 수동 확인만으로 끝내지 않고, 핵심 상태와 QGIS 레이어 트리 동작을 자동 검증한다.

다음은 범위 밖이다.

- 새 데이터 형식이나 외부 지도 공급자 추가
- 전문 GIS 전체 기능을 기본 화면에 노출
- 기존 조사 데이터의 자동 변환 또는 삭제

## 사용자 화면

### 전체 구조

기본 화면은 `단계 안내 | 지도 작업공간 | 검수/도움말`의 세 구역으로 유지한다.

- 왼쪽 상단은 7단계 목록이다. 각 행은 번호, 의미 있는 아이콘, 짧은 작업명, 상태 배지로 구성한다.
- 왼쪽 하단은 레이어 목록이다. 레이어 행에는 가시성, 종류 아이콘, 이름이 있고 드래그로 위아래 순서를 바꾼다.
- 가운데는 가장 큰 지도 캔버스다. 상단에는 현재 단계에서 가장 필요한 1~3개 아이콘 버튼만 보인다.
- 오른쪽은 현재 단계의 목적, 완료 조건, 검수 결과, 다음 행동을 보여준다.

단계를 선택한다고 데이터를 바꾸지는 않는다. 현재 작업에 필요한 명령과 안내만 바뀐다. 단계 완료 상태는 실제 프로젝트와 체크리스트 결과에서 계산한다.

### 7단계와 완료 조건

| 단계 | 사용자에게 보이는 작업 | 완료 판정 | 기본 행동 |
| --- | --- | --- | --- |
| 1 | 새 조사 만들기 | 조사 GPKG와 표준 레이어 존재 | 새 조사 |
| 2 | 배경·지적도 보기 | 배경 또는 지적 레이어가 지도에 표시됨 | 배경 선택 |
| 3 | 조사구역 그리기 | `survey_area` 폴리곤 1개 이상 | 구역 그리기 |
| 4 | 유구·단면선 그리기 | 유구 면 또는 선과 필수 속성 존재 | 유구 면/선 그리기 |
| 5 | GPS 기준점 등록 | 기준점 2개 이상과 필수 측지 메타 존재 | 기준점 등록 |
| 6 | 도면 검수 | error 0건 | 검수 실행 |
| 7 | 제출 패키지 만들기 | 6단계 통과 후 PDF 또는 SHP 패키지 생성 | 제출 패키지 |

단계 7은 숨기거나 비활성화하지 않는다. 검수 오류가 있으면 누를 수는 있지만, 오류 목록과 해결할 단계로 안내하고 실제 내보내기는 차단한다.

### VWorld 빠른 선택

배경 선택은 작은 체크박스와 이름만 나열하지 않는다. 다음 카드를 아이콘과 한 줄 설명으로 표시한다.

- 기본지도: 도로와 지명 확인
- 위성사진: 지형과 현장 흔적 확인
- 지적도: 필지 경계 확인
- 하이브리드: 위성사진 위 지명 확인
- 등고선: 지형 높낮이 확인

각 카드는 가시성 토글과 투명도 조절을 제공한다. 위성사진과 지적도는 함께 켤 수 있다. 지적도는 기본적으로 위성사진보다 위에 배치하며, 사용자가 레이어 목록에서 순서를 바꾸면 그 순서를 존중한다.

아이콘은 텍스트가 아닌 형태로 구분한다. 기본지도는 접힌 지도, 위성사진은 지구와 궤도, 지적도는 분할된 필지, 하이브리드는 지도와 지명 핀, 등고선은 등고 곡선을 사용한다. 모든 아이콘에는 한국어 라벨과 툴팁을 함께 제공한다.

### 레이어 조작과 삭제 안전성

레이어 트리는 QGIS 레이어 트리 모델의 재정렬 기능을 사용한다. 드롭이 끝난 뒤 지도의 렌더 순서가 트리 순서와 같아야 한다. 폴더와 레이어를 구분하고, 다중 선택 드래그는 선택한 레이어 묶음의 상대 순서를 유지한다.

삭제는 레이어 창의 삭제 버튼, 컨텍스트 메뉴, 레이어 창에 포커스가 있을 때의 Delete 키로만 실행한다. 삭제 전에는 대상 개수와 이름을 보여주고 확인을 받는다. 편집 중인 벡터 레이어가 포함되면 저장/취소/계속 중 하나를 선택하게 한다. 삭제 취소는 프로젝트 상태를 바꾸지 않는다.

### VWorld 키와 오류 처리

VWorld 접근 키는 기본값이나 상수로 제공하지 않는다. `QSettings`의 사용자별 설정에서 읽고, 없으면 배경을 처음 사용할 때 설정 안내를 보인다. URL에는 그때 읽은 키만 사용한다. 네트워크 또는 키 오류는 어떤 지도인지와 설정 위치를 설명하는 오류로 표시한다.

## 내부 경계

`MainWindow`는 위젯 배치와 사용자 상호작용만 담당한다.

- 새 `WorkflowGuide` 코어 모듈은 7단계 정의, 프로젝트 상태에서의 완료 판정, 다음 행동과 단계별 안내를 반환한다.
- `LayerOps`는 VWorld 레이어 생성, 가시성, 투명도, 레이어 트리 순서를 담당하며 UI 위젯을 직접 알지 않는다.
- `MainWindow`는 `WorkflowGuide` 결과로 단계 레일과 오른쪽 안내를 갱신하고, `LayerOps`로 지도 작업을 요청한다.
- VWorld 설정은 `QSettings` 래퍼를 통해 읽고 쓴다. 키는 테스트에서 주입 가능해야 한다.

## 테스트와 검증

모든 생산 코드 변경은 먼저 실패하는 테스트를 추가한다.

1. `WorkflowGuide` 테스트는 7단계의 완료/미완료 판정, 검수 오류가 있는 제출 차단, 다음 단계 안내를 검증한다.
2. `LayerOps` 테스트는 키를 주입해 각 VWorld 레이어를 만들고, 위성·지적도 동시 가시성, 투명도, 레이어 트리 재정렬 결과를 검증한다. 실제 네트워크 타일 응답에는 의존하지 않는다.
3. 레이어 삭제 정책 테스트는 취소 시 대상 레이어가 유지되고, 승인 시 선택한 레이어만 제거됨을 검증한다.
4. 빌드 후 기존 `ka_hgis_tests`, `ka_workflow_tests`, CTest 전체와 애플리케이션 스모크 실행을 수행한다.
5. 수동 확인은 새 조사 생성, 위성+지적도 겹치기, 드래그 순서 반영, Delete 키 취소/승인, 검수 오류가 있는 제출 차단, 오류 해소 뒤 패키지 생성을 포함한다.

## 수용 기준

- 초보 사용자가 어떤 단계인지, 다음에 무엇을 해야 하는지, 완료되었는지를 화면에서 알 수 있다.
- VWorld 위성사진과 지적도를 아이콘·라벨만 보고 구분하고 동시에 사용할 수 있다.
- 레이어를 드래그하면 캔버스 렌더 순서가 변경되며, 자동 테스트가 이를 증명한다.
- 모든 레이어 삭제 경로에 확인이 있으며, Delete 키는 레이어 창 포커스에서만 작동한다.
- VWorld 키가 소스나 배포 기본값에 남아 있지 않다.
- 7단계 제출은 체크리스트 error 0건이 아니면 패키지를 만들지 않는다.
